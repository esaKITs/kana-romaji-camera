# MeikiOCR experiment implementation and verification

Date: 2026-10-18 JST. Development head inspected: `7204ac4be05ebf70dafc67ac19f7747a7b3ba80e`. Production at start: `136b066505b23367f9976ff49bfe0954368ef61d`. Production files and main are not modified by this work.

The previous Actions build failed with Vite's `Invalid value "iife" for option "worker.format"`. ES-module Worker output fixes this. The previous branch supplied only a separate text list. This implementation uses the existing camera/controller, rendering, tracking, gestures, Focused scan, Live/Still and unified per-object paper palette. The current production-derived controller also had a missing separator in `await ensureLiveWorker()if`; the experiment fixes that syntax in its derived copy only.

The actual engine is MeikiOCR Web (`0431493cfc59534bdf9e48be95a9e43c21a206be`) + ONNX Runtime Web 1.30.0. A separate module Worker runs WASM with one thread and no proxy worker. GPU/SAB/COOP/COEP are not required. Detector/horizontal recognizer model binaries are separately served, pinned by revision, byte count and SHA-256. The vertical model is not loaded. Models total 33,097,079 bytes; WASM+glue 14,264,278 bytes. Pinned OpenCV (~11MB) and the two existing matching libraries are also served locally. There is no Tesseract runtime or traineddata request in the browser integration test.

The adapter retains Meiki's real per-character boxes, groups contiguous kana without bridging kanji or punctuation, and passes those results into the original extraction/romaji pipeline. The original contextual kana conversion and small dictionary remain. No inferred kanji reading is introduced. A matching furigana result is still required to cover kanji. The old Tesseract-specific serial Live retries are bypassed only for the new provider, allowing each completed scan to be placed immediately. The existing immutable-capture/generation checks remain.

A real browser test exposed another object-change path: optical flow can return early without a matrix, leaving registration status unavailable, so the old palette is not invalidated on a clearly different target. The experiment checks strong appearance change before those early returns. The test then confirms a new object epoch and absence of old labels on the new dark target.

Live label blink correction (2026-10-18): user reported the labels themselves disappearing/reappearing. `trackTick` cleared visible labels after two optical-flow failures (~130ms), while the next OCR result repainted them ~700ms later. Three reproduction assertions fail before this patch for a stationary same-object texture, a transient flow exception, and same-object translation. It never extends unverified display by a timeout: a mismatch still clears the object immediately, and a genuinely uncertain scene still hides labels after two failures. Physical-device blink confirmation remains pending.

Additional false-mismatch regression: sparse optical flow can also propose a bad transform whose registration check reports mismatch on the same textured target. A seventh new raster test reproduces this case. The fallback is therefore attempted for any failed flow transform, including mismatch; only a separately fitted and pixel-verified same-object transform can rescue display. Genuine black/white or different-white object mismatch still clears/hides labels.

Live label position stability (2026-10-18): the user confirmed the blink fix but reported large horizontal/vertical label jitter. Raw flow/homography and OCR boxes were repainted directly with no presentation filter; the block matcher retained a two-point RANSAC hypothesis rather than refitting all agreeing points. The new least-squares similarity fit uses all accepted correspondences. OpenCV prefers that lower-degree transform only when independent image registration verifies it, retaining the full homography fallback for perspective changes. Block matching also refits its inliers. Live presentation separately filters small center/size changes with motion-adaptive low-pass filtering, normalized across OCR resolutions and matched by text plus spatial proximity. Large camera moves/zoom follow immediately; any center lag is bounded to 4 CSS pixels and 20% of label height. OCR evidence, source glyph coordinates, recognition history and Still rendering are not filtered. Object epochs, tracking reset, missing labels and aspect changes invalidate display history.

Eight new regressions cover x/y noise, size pulsing, deliberate/sustained motion, epoch/Still isolation, analysis-resolution changes, evidence immutability, duplicate text rows and noisy multi-point fitting. All 120 tests pass. Synthetic alternating input standard deviation of 3px/2px in x/y becomes 0.901px/0.601px in actual canvas label draw positions (about 70% lower; not a physical-phone measurement). Actual OpenCV/WASM translation, rotation, combined motion, black→white, white→black and different-white-object checks pass 6/6; this script is now included in both GitHub workflows. Long-vowel display implementation (2026-10-18, baseline 3504a2dc775e3f8e6e23458c2a23883f86f4602e): remove global ou/oo/aa/uu/ee/ii replacements. Both display modes share explicit pronunciation units, preserving separate vowels and source offsets. Read-only kana-to-pronunciation mappings are extracted reproducibly from UniDic Lite 1.0.8; all conflicting pronunciations are excluded. Complete lexical lookup and conservative complete-coverage segmentation using reviewed vocabulary/function tails handle known sequences. This is not a full UniDic morphological analyzer. Unknown/ambiguous forms retain their source vowel sequences. Explicit classroom conventions include paatii/pātī, sensee/sensē, omou, teikuauto and oukagaishimasu. No kanji reading is inferred. Nasals use m before m/b/p, n’ before vowels/y, n elsewhere, respecting explicit spaces/punctuation. OCR fragments share context only within a verified join group with nearly touching boxes on the same baseline; source geometry/evidence are unchanged.

The bottom-right aa/ā button is accessible while the camera is running. Stop remains left, Guides centered, Torch above. Storage failures are tolerated; valid preferences survive reload. Switching synchronously repaints existing Live/Still items, without restarting OCR or mutating captures, tracking, palette, history or generation. A delayed OCR result uses the current display preference. Old recognition diagnostics are discarded on object reset to prevent a toggle from restoring previous-object details.
